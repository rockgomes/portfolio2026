<CaseSection title="How it is built" subtitle="the part that was interesting" id="built">
  <CaseBlock label="the idea" title="One moving sale for each seller">
    A moving sale has everything one person sells before they leave. Buyers see all of that person's items in one place.
    <Proof slot="proof" caption="One moving sale: a flat clear-out in Kalamaja, six items." media={img(sale, 'The Kalamaja flat clear-out page in MoveOutSale: one seller, Marta Kuusk from Tallinn, with six items in a grid, among them a grey sofa, an oak dining table, a brass lamp and a cast iron pan.')} />
  </CaseBlock>
  <CaseBlock label="the interesting part" title="A public demo that cannot reach real data">
    The demo uses its own Supabase project (the database and sign-in service). It never has the keys to the real site. The demo signs in every visitor with their own temporary account. Database rules (row-level security) stop visitors from seeing each other's data. A noindex header tells search engines not to list what visitors type.
  </CaseBlock>
  <CaseBlock label="a small thing" title="Reset only when something changed">
    Every night, a scheduled job deletes the demo data and loads the starting data again, but only if someone changed something. On most nights nobody did, so the job does nothing.
  </CaseBlock>
  <CaseBlock label="the stack" title="The database checks who can see what" pills={['Next.js', 'Supabase', 'Playwright']}>
    I built it with Next.js (App Router). Supabase gives the Postgres database, sign-in and file storage. Every table has row-level security, so the database itself checks who can read or change each row. The browser makes photos smaller before it uploads them. Playwright tests cover the main flows.
  </CaseBlock>
</CaseSection>
