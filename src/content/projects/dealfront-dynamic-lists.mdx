<CaseSection title="Three decisions I would defend" subtitle="in the order I made them" id="decisions">
  <CaseBlock label="decision 1 of 3" data-decision="1" title="Views belong to one list" pills={['dropped: a new list every time', 'dropped: views shared across lists', 'chosen: views inside their list']}>
    People made a new list every time they wanted to see a smaller group of companies. I looked at three places to save a filter: as a new list, as a view that every list shares, or as a view inside one list. A new list was the thing we wanted to stop. A shared view did not work, because a group like "low engagement" only makes sense for the list it came from. So each view belongs to one list.
    <Proof slot="proof" caption="The view selector is in the list's own toolbar, under the list name." media={img(toolbar, 'The list header: the list name CRM Connected with its size, 29k, and the Default view selector in the same toolbar, next to the filter and column icons.')} />
  </CaseBlock>
  <CaseBlock label="decision 2 of 3" data-decision="2" title="Save filters and columns together">
    I tried the filter and column controls in a sidebar, a flyout, a popup, a side panel, and a View options modal with tabs that kept growing wider. Then I saw that filters pick which companies you see, and columns pick what you see about them. People need both to describe one view. So the Save as new view window saves filters and columns together.
    <div slot="proof" style={{ maxWidth: '648px' }}>
      <ProofSwitch kind="segmented" id="stage" label="Design stage" selected={1} items={[
        { label: 'Explored', caption: 'Dropped: a modal with one tab for filters and one tab for table setup.', media: img(explored, 'A View options modal with two tabs, Filters and Table. The Filters tab has three columns: available filters, the selected filter, and active filters.') },
        { label: 'Shipped', caption: 'Save as new view: the filters and the columns, each with a count, saved together.', media: img(shipped, 'The Save as new view modal: a view name, Sales CRM, then Filters with a count of 2 and Columns with a count of 6.') },
      ]} />
    </div>
  </CaseBlock>
  <CaseBlock label="decision 3 of 3" data-decision="3" title="Always show which view and filters are on">
    Views only work if people always know what they are looking at. So the page always shows which view and filters are on. If you change a saved view, a "modified" flag shows, with save as new or revert. Default view clears everything, and you cannot overwrite it by accident.

  <CaseBlock label="exploration" title="Five places for the controls" pills={['sidebar', 'flyout', 'popup', 'side panel', 'tabbed modal']}>
    Before the final design, I tried the filter controls in five places. The tabbed modal grew wider with every tab, because I tried to fit filters and table setup into one window. This showed me that filters and columns belong together.
  </CaseBlock>
  <CaseBlock label="filtering" title="A short Filter window">
